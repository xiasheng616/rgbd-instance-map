# 五关路线与独立实现验收

2026-11-08 启动。按每周约 12—15 小时安排，暂估 10—12 周；第一关完成后按实际投入校准。以验收通过推进，不为日期跳过核心能力。以下均为计划，不是已完成结果。

## 第一关：提供位姿下的 RGB-D 多帧融合（约 1—2 周）

**小项目：桌面场景多帧重建器。** 用 TUM 一段序列，读取 RGB、深度和位姿，统一到世界坐标，输出融合点云和相机轨迹。

- 自己写：文本索引读取、时间关联、点云反投影、变换矩阵组装、点坐标变换、融合主流程。
- 可以用：SciPy 四元数转换，Open3D 显示、PLY 写入和体素下采样。
- 新知识：坐标系、齐次变换、四元数接口、时间戳关联、体素。
- 验收：20—50 个采样帧融合，给出单帧/不变换叠加/正确变换三种结果；变换再逆变换恢复原点；换一段帧区间仍能运行。能解释为何不能直接拼接相机坐标点云。
- 交付：可复用读取和几何函数、CLI 入口、PLY、截图和简短记录。

## 第二关：自己估计变换并做配准（约 2—3 周）

**小项目：可诊断的两帧配准器与短序列拼接。** 先在合成点对上验证刚体拟合，再处理真实 RGB-D 点云。

- 自己写：SVD/Kabsch 刚体拟合、最近邻对应筛选、点到点 ICP 迭代、累计变换及旋转/平移误差。
- 可以用：NumPy SVD、KD-tree；Open3D ICP 作为同输入对照。
- 新知识：最小二乘、SVD、ICP、重叠率、局部收敛；正式位姿误差比较前完善时间插值协议。
- 验收：合成已知变换可恢复；真实帧对区分成功和失败；固定点云、初值、距离阈值比较自己的 ICP 和 Open3D。GT 用于误差评价，提供 GT 初值的诊断实验与独立估计结果分开报告。
- 交付：配准脚本、误差与失败表、短序列结果。轨迹不是只靠截图判断。
- 学习入口：[Open3D ICP](https://www.open3d.org/docs/release/tutorial/pipelines/icp_registration.html)。届时先解释 Kabsch 数据流和矩阵形状，再让你实现。

## 第三关：跨帧三维实例地图（约 3 周）

**小项目：同类家具不会反复编号的物体地图。** 接入一个 ARKitScenes 序列，复用二维检测和掩码，将各帧物体观测关联到稳定地图 ID。

- 自己写：数据适配、实例点云生成、几何候选筛选、跨帧一对一关联、拒绝合并、新建/更新实例和体素融合。
- 可以用：已有 Grounding DINO + SAM 2 前端；匹配求解器和点云工具。
- 新知识：数据结构、匹配、空间重叠、遮挡与部分可见性；按实际问题加入外观线索。
- 验收：同物体多视角合并；相邻同类物体分开；离开再看时尽可能复用 ID；记录重复建图和错误合并。先以提供位姿隔离关联问题，再比较估计位姿的影响。
- 交付：带稳定 ID 的场景图、逐实例点云、小型对象记录及关联对照。
- 数据入口：[ARKitScenes 格式与下载](https://github.com/apple-aiml-research/ARKitScenes/blob/main/DATA.md)。只取小范围序列，届时核对单位、内参和位姿方向。

## 第四关：多视角特征与文本检索（约 1—2 周）

**小项目：输入物体描述，在三维地图中找回目标。** 主候选 SigLIP 2，原版 CLIP 作为可选对照。

- 自己写：区域裁剪与特征缓存、归一化、多视角特征聚合、查询排序、目标高亮和证据视图返回。
- 新知识：图文共同特征空间、相似度、多视角聚合、Top-1/Top-K。
- 验收：固定候选地图和查询，比较单视角与多视角特征；编码器对照使用同一批输入，阈值在开发场景选择。几何真值与查询标签不参与测试时决策。
- 交付：检索入口、留出场景查询表、成功及失败案例。简单类别/属性检索不宣称任意空间语言推理。
- 模型入口：[SigLIP 2 Base](https://huggingface.co/google/siglip2-base-patch16-256)。到这一关再安装模型依赖。

## 第五关：多场景评估与 GitHub 交付（约 1—2 周，可与前面并行）

**小项目：可复现的三维实例地图工具。** 初版 3—5 场景，条件允许扩到 5—10 场景；开发与测试按场景隔离。

- 自己写：关键评估、消融运行和失败归因；选一个已理解的几何模块用 C++/Eigen 实现，与 Python 对照。
- 验收：明确重复实例、错误合并、匹配与检索指标的定义；统一部分观测与完整 GT、AABB 与 OBB 的比较约定；报告模块耗时和地图规模。
- 核心对照：不关联 vs 几何关联 vs 几何加外观；单视角 vs 多视角；提供位姿 vs 估计位姿。按问题选必要对照，不要求全排列。
- 助手整理：README、环境与运行说明、结构图、演示、结果表和简历表述。结论只能来自实测，不能保证模型更换后必然提升。
- 最终发布由学习者亲自操作：助手教会检查待提交文件、暂存、提交、创建 GitHub 仓库、设置远端及推送，并帮助排查问题和核对远端结果；助手不代为提交或上传本项目。

## 共同验收规则

每关是一个完整可演示的小项目。验收包括代码、实际结果和一个有意义的迁移任务，以及你对输入、处理、输出和失败原因的解释。不用重复填写配置文件作为练习，也不以“脚本没报错”代替算法验收。

工程整理随阶段完成：入口参数化、职责拆分、必要错误检查、数据和代码分离、少量关键数学正确性检查。先把主流程做通，再抽取确实复用的模块。
